# 網站改版任務清單（給 Codex）

目標：讓登入會員免費使用完整報告與進階功能，並讓 AI 解盤明顯勝過「把命盤貼給 ChatGPT」。
背景研究見 `reports/AI時代 紫微斗數 頂尖工具.md`（未進版控，可能不存在，不影響本清單）。

**一次只做一個任務**，依編號順序。每個任務做完都要通過該任務的「完成條件」與下方的共通檢查。

### 目前驗證狀態

正式建置、字型、Lint、排盤與運限驗算均通過。會員功能以 Firebase 模擬器及本機 AI 回應驗證，涵蓋報告權限與重開、AI 依據與快取、行事曆連結重設、事件定盤與刪除。瀏覽器已測試登入後接續報告、剪貼簿、手機與桌機列印、深度解盤站內通知。

正式環境需設定 Firebase 服務帳戶及 AI，部署後以對外 HTTPS 網址驗證 Google／Apple 行事曆訂閱。重設後，舊連結在伺服器回傳 404；日曆程式既有的快取會依其刷新週期更新。

## 開工前必讀（所有任務適用）

1. 先讀 `AGENTS.md`、`README.md`。本專案用 Next.js 16，API 和慣例跟舊版不同；寫 Next.js 程式前先查 `node_modules/next/dist/docs/`。
2. 架構原則：網站以靜態頁為主，排盤在瀏覽器端完成，只有 `src/app/api/*` 在伺服器執行。不要啟用 `cacheComponents`、Server Actions 或 Next 圖片最佳化。每月營運預算約 NT$500（Netlify + Firebase），不要引入按量計費的服務。
3. 伺服器程式**不可 import `firebase` 套件**。伺服器端一律照 `src/lib/server/firebase.ts` 的做法：用 jose 驗 ID token，用 Firestore REST API 讀寫。
4. 既有公開排盤、知識頁和報告預覽維持公開。原訂付費的功能改為登入會員即可使用。會員 API 必須在伺服器驗證 Firebase ID token，依驗證所得的 uid 限制個人資料的讀寫。改 `firestore.rules` 後要更新並跑 `scripts/check-rules.ts`。
5. 所有運限都要經過 `src/lib/periods.ts` 的 `horoscopeAt`，不可直接呼叫 `astrolabe.horoscope`。農曆換算用 `src/lib/ziwei.ts` 的 `lunarToSolar`，前端不可 import `lunar-lite`。
6. 畫面文字不可出現 Gemini、Google 或任何模型名稱，只寫「AI」（程式註解可以寫）。
7. 人因規範：文字對比 ≥ 4.5:1、一般文字 ≥ 12px（命盤格內 ≥ 10px）、觸控目標 ≥ 44px（桌機也一樣）、手機輸入框 16px、手機與桌機都要 RWD，並支援深色模式。
8. 新增套件要鎖精確版本，而且要挑發布滿兩週的版本。不要升級既有套件，也不要跑 `npm audit fix --force`。
9. 新增或修改中文文案後，先跑 `npm run font:subset`，再 `npm run build`（`font:check` 連註解裡的新字都會擋）。

### 共通檢查（每個任務結束前都要跑）

```bash
npm run lint
npm run font:subset && npm run build
npx tsx scripts/check-readings.ts
npx tsx scripts/check-periods.ts
npx tsx scripts/check-birthtime.ts
```

有改到排盤、運限或曆法時，加跑 `verify-chart.ts`、`verify-lunar.ts`、`verify-periods.ts`、`check-folk.ts`。

### 0-1 資安標頭與設定（已完成）
- `next.config.ts`：設 `poweredByHeader: false`、`images: { unoptimized: true }`，並用 `headers()` 對全站加上：
  - `X-Content-Type-Options: nosniff`
  - `Referrer-Policy: strict-origin-when-cross-origin`
  - `Permissions-Policy: camera=(), microphone=(), geolocation=()`
  - `Cross-Origin-Opener-Policy: same-origin-allow-popups`（不可用 `same-origin`，會讓 Google 登入彈窗失效）
  - `Content-Security-Policy: frame-ancestors 'none'`（只加這一條，完整 CSP 另案處理，以免擋到 Firebase）
- **完成條件**：build 成功；`next start` 後用 curl 確認回應有上述標頭、沒有 `X-Powered-By`；Google 登入彈窗仍可用。

## 2026-11-24 差異化功能與驗收順序

**候選時辰對照（已實作）**。 訪客選「不知道」後，可從十三個時段（子時分早晚）任選兩個，比對十項本命資料。輸入鐘點接近交界或遇到夏令時間切換而有兩種排法時，結果頁直接提供該組對照。分享連結保留當時打開的候選盤。「排盤說明」提供可開啟的台北除夕晚間範例與香港天文台曆表。個性描述和事件定盤供使用者參考，確認實際出生時間仍應核對出生紀錄。

專業工具已經有時辰微調、定盤輔助和 AI 文字盤。本站這一版把在地時間校正、跨日換年和兩張盤的逐項差異放在同一流程。驗收案例包含除夕晚子時跨農曆年、夏令時間回撥和重開分享連結。[紫微斗數排盤](https://apps.apple.com/hk/app/紫微斗數排盤/id445270462) · [文墨天機專業版](https://apps.apple.com/tw/app/文墨天機-專業版/id1193514811) · [香港天文台曆表](https://www.hko.gov.hk/tc/gts/time/conversion.htm)

| 建議順序 | 功能 | 驗收方式 |
| --- | --- | --- |
| 1 | AI 引用連回命盤。從每條引用點開對應宮位，並標出本命、大限或流年層級。 | 使用者能從回答回到正確宮位和運限，再回到原來的問題。 |
| 2 | 擴充可重排的教學命例。以虛構生辰展示日治東京時間、台灣夏令時間、閏月與晚子時。 | 每例附原始輸入、規則、預期結果和來源，能用同一表單重排。 |
| 3 | 命理師覆核紀錄。延續第 4 波的規劃，讓老師能在 AI 初稿逐段留下修訂理由與盤面依據。 | 經授權的老師能分辨原文、修訂與定稿，對外報告只呈現選定版本。 |
